# Общие цели и бюджеты

## Реализация

- Меню плана использует нативный `ShareLink` / `CKShareTransferRepresentation`. Зональный `CKShare` создаётся только после открытия системного окна. Приглашения адресные, участники имеют право записи для публикации своего вклада.
- `CloudPlanSync` хранит отдельную зону `plan_<id>_<UUID>`: `PlanDefinition` (название, валюта, цель/лимит, месяц, обложка) и `PlanContribution` (идентификатор участника, месяц, абсолютная сумма, ревизия).
- Принятие приглашения использует существующий путь AppDelegate → FinanceStore → CloudKitSyncCoordinator. После импорта приложение само открывает выбор личного счёта той же валюты независимо от текущего экрана; у бюджета также выбирается локальная категория. Используется подтверждённый CKShare из результата принятия, а не старое metadata со статусом pending. Незавершённая привязка повторно предлагается при следующем запуске; отмена не открывает лист заново при каждом refresh.
- Привязки и настройки напоминаний остаются в приватном ledger пользователя. Общая зона не содержит счета, операции или их историю. Для разных участников следует выбирать разные личные счета, иначе одинаковый общий счёт будет посчитан дважды.
- Цели суммируют балансы, бюджеты — расходы участников по их категориям за месяц общего бюджета. Повторная доставка абсолютной суммы не прибавляет её второй раз; исправление и удаление операции пересчитывают вклад.
- Локальный вклад берётся из ledger, опубликованный вклад этого же пользователя исключается. Идентичность сохраняется в приватных метаданных для корректного офлайн-расчёта. Pending/удалённые участники исключены, валюты не конвертируются неявно.
- Подлинность определяется по `CKShare` и системным creator/lastModified user record IDs. Участник не может подставить чужой ID в учитываемый вклад. Общая дефиниция принимается от владельца.
- `CKSyncEngine` обрабатывает push, очередь, повторы и конфликты. Outbox и серверные change tags сохраняются в `financium-plan-sync.json`; нет polling. Ошибки синхронизации доступны UI.
- «Закрыть» у владельца удаляет общую зону и сохраняет личный план; у участника — выходит из зоны и удаляет импортированный план. Счета и операции сохраняются. Удаление общего плана владельцем сначала отзывает доступ. Отозванные зоны не пересоздаются из очереди.
- Прогресс общий. Заполнение бюджета показывает оставшуюся долю лимита и уменьшается при расходах; заполнение цели растёт при накоплении. График подписан «Динамика вашего вклада»: чужая история не передаётся, поэтому общий исторический график не выдумывается.

## CloudKit schema

Debug-версия автоматически создаёт оба типа при запуске CloudKit sync. Инициализатор записывает два синтетических образца в отдельную приватную зону `FinanciumSchema`. Образцы не импортируются в ledger, реальные планы и приглашения не создаются. Повторный запуск обновляет те же записи. В Release/TestFlight этот код отсутствует.

Порядок: запустить Debug из Xcode с доступным iCloud и Development-окружением → дождаться в консоли `Shared plan schema initialized` → открыть CloudKit Console → **Deploy Schema Changes**. При ошибке инициализации консоль выводит исходную причину; повторить можно следующим запуском Debug. Публикацию Production-схемы приложение само не выполняет.

Перед выпуском в Production должны быть опубликованы два record type:

| Record type | Поля |
| --- | --- |
| `PlanDefinition` | `payload`: Bytes, `updatedAt`: Date/Time |
| `PlanContribution` | `payload`: Bytes, `updatedAt`: Date/Time |

Используются private custom zones и системный zone sharing; отдельный public database не нужен. Схему следует перенести из Development в Production стандартным Deploy Schema после проверки подписанной Development-сборки. Изменения схемы из этой задачи не публиковались.

## Проверка

В этой задаче выполнены только разбор Swift-синтаксиса без сборки, проверка локализаций и `git diff --check`. Сборка и исполняемые тесты не запускались по просьбе пользователя.

На двух устройствах с разными iCloud-аккаунтами проверить:

1. Пригласить участника в цель: проверить закрытое и уже открытое приложение. После принятия выбор счёта должен появиться автоматически. Привязать счета: 20 000 + 30 000 = 50 000. Проверить отмену выбора, повторное открытие ссылки и следующий запуск приложения.
2. Общий бюджет: расходы 500 + 1 000 = 1 500; повторная доставка не меняет сумму. Изменение/удаление расхода обновляет итог.
3. До принятия приглашения badge общего плана отсутствует. После принятия появляется. Личная категория участника может отличаться от категории владельца.
4. Офлайн-изменение, перезапуск и восстановление сети; параллельное изменение со второго устройства того же пользователя.
5. Выход участника, отзыв ещё не принятой ссылки, закрытие владельцем, удаление общего плана, повторное приглашение.
6. Смена месяца/категории/счёта; архивирование и удаление привязанного счёта; отсутствие счёта нужной валюты; sign out/switch iCloud.
7. Проверить Production после Deploy Schema. Runtime-работа CloudKit этой задачей не подтверждена.
