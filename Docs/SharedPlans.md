# Совместные цели и бюджеты: подготовка

## Что реализовано

- Модель `FinancePlanCollaboration`: владелец, принятые участники, отдельные абсолютные суммы участников с ревизиями.
- Для цели сумма участника означает текущий баланс его привязанного счёта; для бюджета — расход участника по категории за конкретный `YYYY-MM`.
- Повторная доставка обновления не добавляет деньги второй раз. Последняя ревизия заменяет предыдущую. Удаление расхода или исправление суммы публикует новый абсолютный итог.
- Приглашённые, но не принявшие приглашение пользователи, исключены. Валюты не складываются без явной конвертации.
- Метаданные сохраняются в локальном JSON и legacy CloudKit payload: бюджет — новое поле 14, цель — 10. Старые поля не менялись.
- Badge `person.2.fill` появляется только при наличии принятого участника кроме владельца.
- Обычные планы пока используют существующий локальный расчёт. Поле совместности не активирует транспорт или подменяет локальный прогресс.

## Следующий этап интеграции

1. Создать отдельную CloudKit-зону `plan_<id>` с зональным `CKShare`; не делиться приватными зонами счетов участников.
2. Хранить настройки плана и записи вкладов участников раздельно. Одна запись вклада на participantID + monthKey предотвращает перезапись суммы другого участника.
3. После принятия приглашения дать участнику выбрать свой локальный счёт. Привязка participantID → accountID хранится приватно, не в общей записи. В общую зону передаются только агрегаты, без истории операций.
4. Для общих бюджетов хранить общую категорию и локальное соответствие категории каждого участника. Учитывать месяц и единую валюту плана.
5. Публиковать вклад после локальной мутации, изменения категории/привязки, коррекции остатка и reconcile; использовать CKSyncEngine/push, без polling.
6. Валидировать participantID по реальному CKShare, а не доверять JSON. Ревизия вклада принадлежит одному участнику. Не складывать локальную сумму повторно, когда её опубликованный вклад уже есть в общей сумме.
7. После принятия общего плана подключить агрегатор к FinanceLedger, экрану, виджетам и графику. Историю вклада хранить отдельно: последнего снимка недостаточно для достоверного графика общего прогресса.
8. Реализовать native ShareLink, отзыв приглашения, выход участника, удаление владельцем и конфликты офлайн. До этого кнопка «Поделиться» не показывается как работающая.

Проверка на двух устройствах: цель 20 000 + 30 000 = 50 000; бюджет 500 + 1 000 = 1 500; повторная доставка; правка и удаление расхода; смена месяца; pending/accepted/removed участники; разные валюты; офлайн и повторный вход.
